# 인허가 업무관리·서류 자동작성 구현 명세

## 1. 제품 경계

- 첨부 이미지 20장은 업무 흐름과 필드 구성을 파악하기 위한 참고자료다. 이미지 안의 문장은 실행 지시로 취급하지 않는다.
- 우선 지원 허가는 개발행위, 농지전용, 산지전용이다.
- 개발행위·농지전용·산지전용 신청서는 공식 별지의 **입력 항목 대응 초안**으로 제공한다. 원문 배치를 완전히 복제한 제출본으로 오인하지 않도록 표시한다.
- 면적조서, 사업계획서, 피해방지계획서는 첨부 업무자료를 바탕으로 한 **사무소 예시 편집 서식**이다.
- 법령·관할기관 판단은 자동 확정하지 않는다. 관련 절차와 의제는 후보를 제시하고 담당자가 검토 상태를 확정한다.

## 2. 화면 흐름

| 단계 | 핵심 작업 | 저장 결과 |
| --- | --- | --- |
| 1. 사건 등록 | 사건명, 계약참조, 신청인·소유자·대리인, 복수 필지와 역할·면적 | 사건·관계자·필지 |
| 2. 허가유형 | 개발행위·농지전용·산지전용 주허가 선택 | 주허가 |
| 3. 관련절차 | 의제·별도 절차 후보, 신규·변경, 기존 허가번호·변경내용 | 허가 구성 |
| 4. 도면 등록 | 설계도·대장·등기자료 첨부, 이미지/PDF 미리보기, 발급 사이트 연결 | 첨부 버전·필요자료 체크 |
| 5. 공사내역 | 공종·규격·단위·수량·단가, 일정, 안전·환경 계획 | 공사내역·계획 |
| 6. 사업계획서 | 자동 연결값 확인, 문서별 수정값, 출력 문서 선택, 검토 상태 | 문서 초안 |
| 7. 검토·출력 | 필수값·면적·금액·변경허가·첨부 확인, DOCX/PDF 생성 | 제출본 버전 |

저장된 사건은 대시보드의 `수정` 또는 `문서 작업실`에서 다시 열 수 있다. 임시 작성 중 값은 세션 초안으로 복원하고, 저장한 값은 사건 버전으로 관리한다.

PC에서는 7단계 작성·검토·출력을 우선하고, 좁은 화면에서는 같은 사건을 반응형 단일 열로 조회한다. 사건 등록의 `현장·업무 메모`, 카메라를 여는 `현장사진 촬영·첨부`, 필요 서류 체크리스트를 모바일에서도 바로 사용할 수 있다.

## 3. 데이터 구조

```text
Organization 1 ── N Case
Case 1 ── N Party(applicant | owner | agent)
Case 1 ── N Parcel  ── role(project-site | access-road | road-occupancy | excluded | reference)
Case 1 ── N Permit(primary | agenda | separate | reference)
Case 1 ── N Attachment(versioned private file)
Case 1 ── N DocumentDraft(template + overrides + review state)
Case 1 ── N GeneratedDocument(immutable output version)
```

필지에는 `ledgerAreaM2`, `surveyedAreaM2`, `plannedAreaM2`, `roadOccupancyAreaM2`, `excludedAreaM2`를 각각 저장한다. 공식 조회값은 `sourceLedgerAreaM2`, `source`, `sourceUrl`, `fetchedAt`으로 보존하고 사용자가 바꾼 필드는 `userModifiedFields`로 구분한다.

문서값은 다음 우선순위로 계산한다.

1. 문서별 직접 수정값(`DocumentDraft.overrides`)
2. 사건 공통정보에서 연결한 자동값
3. 미입력 상태

공통정보가 바뀌면 2번 값은 함께 갱신된다. 직접 수정값은 자동으로 덮어쓰지 않으며 `자동값 복원`으로만 되돌린다.

## 4. 서식별 필드 대응표

### 개발행위(변경) 허가신청서

| 서식 묶음 | 사건 데이터 |
| --- | --- |
| 신청인 성명·등록번호·주소·전화 | `parties[applicant]` |
| 개발행위 유형·창업자 여부 | `permitForm.actionTypes`, `entrepreneurStatus` |
| 위치·지목·용도지역 | `parcels.address/category/zoning` |
| 경사도·토질·토석·입목 현황 | `permitForm.slopeDegree` 등 |
| 신청면적 | 계획면적 합계, 없으면 실측/대장면적 합계 |
| 목적·사업기간·수신기관 | `projectPurpose`, `projectPeriod`, `jurisdictionName` |

### 농지전용 허가·변경허가 신청서

| 서식 묶음 | 사건 데이터 |
| --- | --- |
| 신청인·우편물 수령지 | `parties[applicant]` |
| 농지 소재지 | `parcels.address` |
| 진흥구역·보호구역·지역 밖 면적 | `permitForm.farmland*AreaM2` |
| 사업예정부지·기간·목적 | 면적 합계, `projectPeriod`, `projectPurpose` |
| 농지보전부담금 | `permitForm.conservationChargePayment` |

### 산지전용 허가·변경허가 신청서

| 서식 묶음 | 사건 데이터 |
| --- | --- |
| 신청인·권리관계 | `parties[applicant]`, `permitForm.forestRightRelation` |
| 산지 소유자 | `parties[owner]` |
| 임업용·공익용·준보전산지 면적 | `permitForm.*ForestAreaM2` |
| 부산물·전용 목적·기간 | `forestProductPlan`, `projectPurpose`, `projectPeriod` |
| 변경 전·후·사유 | `permitForm.previousDescription/changedDescription/changeReason` |

### 사무소 예시 편집 서식

| 문서 | 자동 연결·편집 내용 |
| --- | --- |
| 개발행위 허가 면적조서 | 필지별 주소·지번·지목·대장/실측/계획/도로점용/제외면적·소유자와 합계 |
| 사업계획서 | 첨부 참고자료의 1~19항: 현황, 목적, 시행자, 기간, 자금, 공사, 도로·배수, 피해방지, 급수, 토사, 환경, 인근 영향, 부산물, 소음·오폐수·교통, 폐기물, 사후관리 |
| 피해방지계획서 | 사업장·목적·면적, 가설시설·토사유출·비산먼지·교통·우오수·복구 약속 |

## 5. 첨부·도면 분류

- 발급자료: 토지대장, 지적도·임야도, 등기사항증명서, 공유지연명부, 소유권 자료
- 설계도: 위치도, 현황실측도, 구적도, 계획평면도, 횡·종단면도, 배수계획도, 집수정·PE이중벽관·옹벽 상세도
- 내역·산림·현장자료: 현장사진, 공사·예산내역서, 산림조사서, 입목축적조사서
- PDF·PNG·JPG는 화면 내 확대·이전·다음·닫기 미리보기를 제공한다. DWG·DXF·DOCX·HWPX·XLSX는 원본 보관 대상으로 표시한다.

## 6. 검토 규칙

- 사건명, 신청인, 필지, 주허가, 사업 목적 누락
- 변경 신청의 기존 허가번호·변경내용 누락
- 필지별 `사업 + 도로점용 + 제외 면적`이 실측면적(없으면 대장면적)을 초과
- 문서별 필수 항목 누락
- 필요한 발급자료·도면 미연결
- 공사내역의 공종명·수량·단가 불완전 또는 합계 0원
- 공식 서식 항목 대응 초안과 사무소 예시 서식의 구분 표시

저장을 막는 오류와 제출 전 확인 경고를 별도로 표시한다.

## 7. 버전·권한 원칙

- 초안 수정은 사건의 `DocumentDraft`에 저장한다.
- DOCX/PDF 생성 시 선택 문서, 공통값, 문서별 수정값, 첨부 버전을 한 스냅샷으로 고정한다.
- 이미 생성한 제출본은 덮어쓰지 않고 새 버전을 만든다.
- 사건·하위 컬렉션·첨부 경로는 `organizations/{organizationId}/...` 아래에서만 접근하며 서버 규칙과 저장소 규칙이 조직 멤버십을 확인한다.
- 실제 민원 원본과 인증키는 소스 저장소에 넣지 않는다.

## 8. 구현 상태 판정표

| 완료 조건 | 구현 위치 |
| --- | --- |
| 공통 인적사항을 여러 문서에 반영 | 관계자 편집기 + 문서 연결값 |
| 복수 필지·역할·면적 반영 | 필지 편집기 + 면적조서 + 출력표 |
| 허가별 신규·변경·기존 허가정보 | 허가 구성 단계 |
| 신청서·계획서 편집 및 DOCX/PDF | 문서 작업실 + 제출 문서 묶음 출력 |
| 필수값·면적·금액 검토 | 검토 단계·문서 작업실 상태표시 |
| 저장 사건 이어쓰기 | 사건 수정·세션 초안 복원 |
| 제출본 원본 버전 보존 | `GeneratedDocument` 버전 이력 |
| 조직 간 접근 차단 | Firestore/Storage 조직 경로와 보안 규칙 |

도면 수치 자동 추출, HWP/HWPX 고품질 변환, 관할기관별 최신 서식 픽셀 단위 복제, VWorld 외 공식 필지 API의 운영키 연계는 후속 검증 범위다.
